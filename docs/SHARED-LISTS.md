# Совместные списки MonoTask 2.1

## Использование

Общие списки автоматически появляются в **Пространстве** как папки с аватарками участников. На iPhone управление доступно также через **Настройки → Общие папки** или кнопку под сеткой папок. На Mac — **Общие списки** в боковом меню.

1. Создайте список. Его создатель становится владельцем.
2. Откройте **Участники → Создать приглашение** и отправьте ссылку или код через системное меню «Поделиться».
3. Второй пользователь открывает ссылку и нажимает **Открыть в MonoTask**: после входа папка подключается и сразу открываются её задачи, без второго «Принять». Сканер внутри приложения и импорт изображения с QR-кодом работают так же. При ручном вводе кода достаточно одной кнопки **Открыть папку**.
4. В общей задаче доступны заметки, подзадачи, приоритет, статус выполнения и ответственный из участников списка.

Приглашение одноразовое, действует 72 часа. Новое приглашение отменяет предыдущее неиспользованное. Владелец может переименовать или удалить список, приглашать и удалять участников. Участник может покинуть список. Удаление участника сбрасывает назначения на него и отзывает использованные им и ещё неиспользованные приглашения; повторный вход требует нового приглашения владельца.

## Хранение и доступ

Личные SwiftData-модели и восемь личных таблиц не изменены. Общие списки используют отдельные таблицы `monotask_shared_lists`, `monotask_shared_members`, `monotask_shared_tasks`, `monotask_shared_invites` и отдельный JSON-кэш, привязанный к ID вошедшего аккаунта. Общие задачи не попадают в личную аналитику.

RLS разрешает чтение только участникам активного списка. Прямые клиентские записи запрещены, даже владельцу; изменения проходят через RPC с проверкой аккаунта, членства и роли. Функции `SECURITY DEFINER` закрепляют пустой `search_path`, используют полные имена таблиц и недоступны роли `anon`. Сервер хранит только SHA-256 кода приглашения. Ключи администратора в приложение не добавляются.

Синхронизация идёт после правок, при активации приложения и восстановлении сети; открытый раздел дополнительно обновляется каждые 6 секунд. WebSocket Realtime не используется. Обновления статуса личной синхронизации и общих списков независимы.

Правки существующих общих списков сохраняются в локальную очередь без сети. Создание списка, приглашения, вступление и управление доступом требуют сети. Каждая задача имеет серверную ревизию: устаревшее изменение не перезаписывает чужое. При конфликте пользователь выбирает общую или локальную версию. Если задачу уже удалили, сохранение локальных правок создаёт новую копию с новым ID. После подтверждённого отзыва доступа к списку его кэш и очередь очищаются.

## Развёртывание

Для нового проекта сначала примените `docs/supabase_schema.sql`, затем [миграцию общих списков](migrations/20261028_shared_lists.sql). Миграция транзакционная и повторяемая; личные политики `owner_only` она не меняет. Для существующего проекта нужна только новая миграция.

28 октября 2026 миграция применена к действующему проекту MonoTask через SQL Editor. Проверены отказы реального Data API для анонимных запросов. [Транзакционный smoke-тест](../tests/shared/live-rollback.sql) успешно проверил создание списка, создание и изменение задачи, ревизии, конфликт, приглашение и чтение snapshot от роли `authenticated`; тест завершён `ROLLBACK`, записи не сохранялись. Для этого не потребовалась установка дополнительного плагина или изменение настроек Safari.

## Проверки

Локальная проверка RLS в PostgreSQL 17 с тремя отдельными аккаунтами и ролями `anon`/`authenticated`:

```sh
tests/shared/run-security.sh
```

Скрипт требует запущенный Docker, использует одноразовый контейнер и удаляет его после проверки. `.env` и рабочая база не используются. Применяются личная схема, миграция дважды для проверки повторяемости, затем 47 проверок. Среди них изоляция личных задач, запрет обхода RPC, отзыв доступа, повторное и просроченное приглашение, неверный ответственный, конфликт ревизий и защита удалённых задач от запоздалого создания.

Кэш и приглашения, без сети:

```sh
swiftc -swift-version 6 MonoTask/Models/SharedList.swift tests/shared/main.swift -o /tmp/monotask-shared-model-tests
/tmp/monotask-shared-model-tests
```

22 проверки покрывают очередь, повторное открытие кэша, более новые правки во время запроса, потерянный HTTP-ответ, конфликты, удаление, отзыв доступа и разбор ссылок.

`SharedListUITests` использует `--screenshots --shared-preview`: отдельные демонстрационные данные без доступа к рабочему серверу. Проверяются создание списка и общей задачи, заметки, подзадачи, выполнение, приглашение, удаление участника и проверка кода. Вместе с регрессиями личных задач — 21 UI-тест.

Проверки серверного транзакционного сценария не заменяют испытание отправки приглашения через сторонний мессенджер и одновременной работы двух физических устройств. Эти действия пользователи выполняют в обычных аккаунтах; автоматические тесты не отправляют сообщения и не создают постоянные аккаунты.

Официальные принципы доступа: [Supabase RLS](https://supabase.com/docs/guides/database/postgres/row-level-security), [Database functions](https://supabase.com/docs/guides/database/functions).

## Страница приглашения (2.1.1)

Меню «Поделиться» отправляет URL `https://tihshkel.github.io/Mono-Task/join/#<код>`. GitHub Pages репозитория [tihshkel/Mono-Task](https://github.com/tihshkel/Mono-Task) публикует `main:/docs`, файл `.nojekyll` отключает обработку Jekyll. Уже отправленные ссылки `egoar777.github.io/MonoTask/join/` по-прежнему разбираются. Страница предлагает явно открыть `com.monotask.ios://join?code=<код>` или скопировать код для ручного вступления. Это переход по нажатию, без Universal Links и автоматического перенаправления. На устройстве требуется установленный MonoTask 2.1 или новее.

Код находится во фрагменте и не передаётся серверу страницы. Страница не проверяет членство, срок и использование приглашения: это делает RPC в авторизованном приложении после явного открытия ссылки или сканирования QR-кода. Дополнительного подтверждения в приложении нет. Личные данные и название списка на странице не отображаются. Старые ссылки и ввод голого кода поддерживаются.

Во время подключения приложение показывает фирменную папку и статус загрузки, а не форму с техническим кодом. Код доступен в свёрнутых подробностях. При ошибке можно повторить попытку или ввести другое приглашение. Если вступление уже выполнено, но задачи не загрузились, повторная попытка только обновляет данные, не принимает код снова. Фоновая активация не пересоздаёт текущее приглашение; новый входящий код не стирается завершением предыдущего.

Страница использует актуальную папку-персонажа, палитру приложения, светлую и тёмную темы по настройкам устройства. Нажатие на иллюстрацию раскрывает открытку «Место для вас»; при уменьшении движения переходы отключены. В карточке ссылки настроены Open Graph и Twitter Card с отдельной обложкой 1200 × 630. Название конкретной папки, код приглашения и имена участников в метаданные не попадают.

Логотипы, обложка и шрифт находятся в `docs/join/assets` и загружаются с того же домена. Экспорт использует текущий BrandLogo и настоящий SwiftUI-компонент папки; после изменения брендинга его можно повторить на Mac:

```sh
swiftc -swift-version 6 -target arm64-apple-macos15.0 \
  MonoTask/Theme.swift MonoTask/Extensions/Color+Hex.swift MonoTask/Models/SharedList.swift \
  MonoTask/Views/Components/FolderArtwork.swift scripts/export-invitation-assets.swift \
  -o /tmp/monotask-export-invitation-assets
/tmp/monotask-export-invitation-assets "$PWD"
```

Проверки страницы: `node --test tests/shared/invitation-web.test.cjs`. Проверяются парсер, запрет открытия повреждённых ссылок, ручной ввод, изменение фрагмента, копирование с запасным вариантом, открытка и локальные ресурсы превью. Перед публикацией проверить мобильную ширину, клавиатурную навигацию и обе темы. Изменения становятся публичными после публикации `main:/docs`; ранее отправленные сообщения могут сохранять закэшированную карточку, а её окончательное размещение выбирает мессенджер.
