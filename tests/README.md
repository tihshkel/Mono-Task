# Проверки

## Сроки задач и уведомления заранее

В редакторе задачи дата срока независима от уведомления. Можно выбрать интервал из списка, свой интервал или оставить срок без уведомления. Планировщик пропускает уже прошедшее время уведомления; перенос срока заменяет запрос с тем же ID, выполнение отменяет запрос.

```sh
swiftc MonoTask/Services/Supabase/SupabaseDTOs.swift tests/deadlines/main.swift -o /tmp/monotask-deadline-sync-tests
/tmp/monotask-deadline-sync-tests
```

Проверяются явные null для удаления срока и отключения уведомления, сохранение своего интервала и совместимость со старой схемой. Для синхронизации интервалов примените `docs/migrations/20261030_task_deadline_reminders.sql`. До миграции интервал работает локально и остаётся в очереди обмена; обычные задачи продолжают синхронизироваться.

В мобильном быстром вводе проверить выбор существующей папки, создание папки с указанным именем и с именем задачи, отмену без появления папки и последовательный ввод в новую папку.

## Планировщик уведомлений

Проверки запускаются без приложения и подключения к Supabase:

```sh
swiftc -D PLANNER_TEST MonoTask/Services/NotificationService.swift tests/main.swift -o /tmp/monotask-planner-tests
/tmp/monotask-planner-tests
```

Проверяются выключение напоминаний, даты в прошлом, выполненные задачи, фильтры утреннего плана, скрытие названий, горизонт расписания и переход на зимнее время.

## Форматирование

```sh
xcrun swift-format lint --strict --recursive MonoTask tests
```

Настройки форматирования находятся в `.swift-format`.

## Проверки интерфейса

### Приглашения в общую папку

В `SharedListUITests` сценарии `testInvitationOpensFolderWithoutSecondConfirmation` и `testManualInvitationOpensFolderWithOneAction` проверяют прямое открытие папки по ссылке и единственное действие при ручном вводе. `testInvitationFailureOffersRetryAndKeepsCodeInDetails` проверяет ошибку, повтор, скрытый код, смену приглашения и отмену. Используется только демонстрационный режим `--screenshots --shared-preview`; дополнительный `--shared-join-error` имитирует отказ без обращения к серверу. Реальный скан камерой и импорт QR-изображения дополнительно проверить на устройстве: после распознавания должна сразу открыться папка, без «Принять».

### Первое знакомство

При первом запуске без сохранённого входа показываются четыре экрана: папки, добавление, выполнение и приоритет. «Начать» сохраняет `monotask_onboarding_completed` на устройстве и открывает вход/регистрацию. После перезапуска и выхода из аккаунта знакомство не повторяется; восстановленный аккаунт сразу открывает задачи. При уменьшении движения иллюстрации статичные, при уходе в фон анимации останавливаются.

Аргумент Debug-сборки `--onboarding-preview` на Mac и симуляторе открывает знакомство без изменения флага и без запуска облачной сессии. `OnboardingTests` проверяет все четыре шага, возврат назад и переход к входу/регистрации: `xcodebuild test … -only-testing:ReviewUITests/OnboardingTests`. В обычном запуске дополнительно проверить завершение → перезапуск → вход без повторного знакомства, а также VoiceOver, крупный текст и обе темы.

### Быстрый ввод на Mac

`tests/ui/mac/CaptureTests.swift` проверяет ⌘N на главном экране и в папке: ввод с клавиатуры, сохранение черновика при повторной команде, закрытие по Esc и кнопке, создание в выбранной папке и сохранение приоритета. Проверки работают с отдельной Debug-сборкой `com.monotask.capturepreview` и базой в памяти. Обычное приложение и его данные не используются. При системном уменьшении движения карточка появляется без наклона, масштаба и смещения. Тайм-аут `enabling automation mode` возникает до выполнения сценариев; в таком случае их можно проверить вручную в этой отдельной сборке.

```sh
xcodebuild -project MonoTask.xcodeproj -scheme MonoTask -destination 'platform=macOS' \
  -derivedDataPath /tmp/MonoTaskCaptureReview build CODE_SIGNING_ALLOWED=NO \
  PRODUCT_BUNDLE_IDENTIFIER=com.monotask.capturepreview
xcodegen generate --spec tests/ui/mac/project.yml --project /tmp/MonoTaskMacCaptureReview
xcodebuild -project /tmp/MonoTaskMacCaptureReview/MonoTaskMacCaptureReview.xcodeproj \
  -scheme Capture -destination 'platform=macOS,arch=arm64' test
```

### iPhone

`WorkspaceFolderListTests` проверяет раскрывающийся список папок: независимое сворачивание, сохранение состояния при переключении вида, выполнение и возврат задачи, открытие редактора, удаление с отменой, создание задачи в выбранной папке и поиск внутри личных и общих папок. Используется база в памяти и демонстрационный общий список без сети. После каждого сценария восстанавливается исходный вид папок. Запуск отдельного набора: `xcodebuild test … -only-testing:ReviewUITests/WorkspaceFolderListTests`.

В Debug-сборке для симулятора аргумент `--scroll-gesture-test` открывает 40 задач в базе в памяти. Облачная сессия не запускается; данные пропадают после завершения приложения. На физическом устройстве и в Release этот режим отсутствует.

```sh
xcrun simctl launch booted com.monotask --scroll-gesture-test
```

Перед выпуском проверить:

- Прокрутку по обеим сторонам строк и диагональными жестами.
- Короткий и полный свайпы удаления, повторный свайп и закрытие действия.
- Отмену удаления кнопкой и завершение по таймеру.
- Открытие и закрытие клавиатуры кнопкой и прокруткой; возврат поля на исходную высоту.
- Положение и доступность отмены над полем с открытой и закрытой клавиатурой.
- Добавление задачи, очистку поля, редактирование и подзадачи.
- Выполнение задачи и обновление аналитики.
- Переходы между задачами, аналитикой и настройками.

Синхронизацию, фоновые уведомления и офлайн-режим проверять отдельно на тестовом аккаунте и двух устройствах.

## Скриншоты

Аргумент `--screenshots` открывает демонстрационную базу в памяти в Debug-сборке симулятора или macOS. Дополнительные аргументы `--activity` и `--settings` выбирают соответствующий экран. Скриншоты в README сняты в этом режиме; личные данные не используются.

## Проверка обновлённого интерфейса

В `tests/ui` находится отдельный проект UI-проверок, не изменяющий схемы приложения. Для запуска нужен XcodeGen и запущенный симулятор. Сначала соберите Debug приложения и установите его **только в симулятор**, затем сгенерируйте тестовый проект во временной папке:

```sh
mkdir -p /tmp/MonoTaskUIReview
cp tests/ui/ReviewTests.swift tests/ui/project.yml /tmp/MonoTaskUIReview/
xcodegen generate --spec /tmp/MonoTaskUIReview/project.yml --project /tmp/MonoTaskUIReview
xcodebuild -project /tmp/MonoTaskUIReview/MonoTaskUIReview.xcodeproj -scheme Review \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test CODE_SIGNING_ALLOWED=NO
```

Проверки используют `--screenshots`: базу в памяти без входа в облачный аккаунт. Проверяются выполнение и прогресс, фильтры списка, сохранение дней категории, периоды аналитики и подробности дня, открытие/закрытие статуса и быстрый ввод после закрытия окна.

Дополнительные аргументы демонстрационного режима:

- `--settings --settings-categories` — список категорий.
- `--settings --settings-edit` — редактор категории и расписания.
- `--settings --settings-sync` — аккаунт и синхронизация.
- `--activity --activity-year` — годовой календарь; `--activity-week` — неделя.
- `--activity --activity-categories` — сравнение категорий.
- `--activity --activity-day` — подробности дня.
- `--sync-success --sync-details` — демонстрационный успешный статус и его детали. Реальная синхронизация не выполняется.
- `--animate-completion` — выполнение первой задачи через две секунды для записи анимации.

## Клавиатура и обновление свайпом

`MotionAndRefreshTests` проверяет схлопывание шапки и восстановление исходных размеров при трёх открытиях клавиатуры, сохранение введённого текста, завершение обновления после изменения состояния интерфейса, продолжение обмена после отмены вызывающей задачи и компактное окно с кнопкой высотой 52 pt.

Для двух проверок жизненного цикла запроса используется `--screenshots --sync-preview`: вместо сети выполняется задержка с обычной сменой состояний сервиса. Дополнительный `--cancel-sync-request` отменяет вызывающую задачу через 50 мс. Эти аргументы работают только в Debug-сборке симулятора, не используют облачный аккаунт и не подменяют проверку реального обмена с сервером.

## Главный экран настроек

`SettingsOverviewTests` проверяет переходы из карточки аккаунта, строк превью расписания и пункта уведомлений, отсутствие изображения профиля и обновление подписи оформления при смене плотности списка. Проверка возвращает исходное значение плотности.

`WorkspaceSharingTests` проверяет общую папку и имена её участников в пространстве, переход к задачам и доступу, автоматическое появление созданной общей папки, её поиск, карточку профиля и переключение тем. Используются `--screenshots --shared-preview`, база в памяти и демонстрационный кэш без обращения к рабочему серверу. Запуск отдельного набора: `xcodebuild test … -only-testing:ReviewUITests/WorkspaceSharingTests`.

## Модели и сохранение на диск

Проверка использует настоящие модели SwiftData и временный файл хранилища, не затрагивая данные приложения:

```sh
swiftc -swift-version 6 MonoTask/Models/*.swift MonoTask/Theme.swift \
  MonoTask/Extensions/Color+Hex.swift MonoTask/Extensions/Date+Extensions.swift \
  MonoTask/Services/FocusService.swift tests/models/main.swift -o /tmp/monotask-model-tests
/tmp/monotask-model-tests
```

Проверяются повторное открытие хранилища, заметки, связи категорий, порядок и прогресс подзадач, выполнение и отмена выполнения, фильтры, расписание и каскадное удаление. Временная база удаляется после проверки.

## Версия 2.0

`FloatingNavigationTests` проверяет ввод в два шага из другого раздела, стекло над прокручиваемым списком до физического нижнего края, удаление и отмену без уменьшения области списка. `TaskEditingTests` проверяет сохранение заметок и подзадач после закрытия редактора, создание категории и сохранение расписания. `ReviewTests` также сравнивает вертикальные координаты трёх больших заголовков и отсутствие статуса синхронизации в аналитике.

После `--settings` можно добавить `--settings-appearance` для прямого открытия вида списка. Все режимы демонстрации ограничены Debug; конфигурация Release использует обычное приложение.

Полный UI-прогон — та же команда `xcodebuild test` без `-only-testing`. Для однозначного выбора симулятора используйте `-destination 'id=UDID'`.

Сетевые UI-проверки используют тестовый транспорт. Они подтверждают жизненный цикл и отмену запроса, но не подтверждают обмен с реальным Supabase, доставку уведомлений системой или работу с реальными учётными данными.

### HTTPS-приглашения

`node --test tests/shared/invitation-web.test.cjs` проверяет новые ссылки, старую схему, повреждённые коды и подмену домена. UI-сценарий `SharedListUITests/testInvitationOpensJoinSheet` проверяет передачу кода в форму и подтверждение в демонстрационном списке. Дополнительный `testLiveHTTPSInvitationOpensApp` открывает опубликованную страницу в Safari и проверяет переход в приложение. Для него передайте `MONOTASK_TEST_LIVE_INVITE=1` в окружение тестового процесса; без флага он пропускается, чтобы обычные UI-тесты не зависели от сети.
